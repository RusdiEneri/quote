# Anti-Slop UI Audit #001

- **Date:** 2026-10-11
- **Target Component:** Mobile Navbar Header (`frontend/index.html`, `frontend/src/styles/base.css`, `frontend/src/styles/components.css`)
- **Mode:** Mode 2 (After)
- **Viewport Tested:** 390x844 (Mobile), 502px (Compact Window), and 768px (Tablet) via Chrome DevTools

## Numbered Findings List

### 1. [HIGH] R-03 (Mobile Responsiveness) — Flex-shrink collision crushes `.brand` to 0px width
- **Violated Rule:** R-03 — Mobile Responsiveness (Hard Gate: HIGH)
- **Reason:** `.brand` has `flex-shrink: 1; min-width: 0;` while `.nav-actions` has `flex-shrink: 0;`, crushing the logo and title to 0px width and causing text like "Studio" to render underneath status badge and theme toggle buttons.
- **Evidence:** DevTools measurement at 390px-502px shows `.brand` width = `0px`, with text colliding directly beneath `.status-badge` and `#themeToggleBtn`.
- **Proposed Fix:** Set `flex-shrink: 0` and `min-width: max-content` on `.brand`; hide decorative sub-elements (`.brand-tag`) on small viewports while preserving `.brand-title` readability.

### 2. [HIGH] R-03 (Mobile Responsiveness) — `.nav-actions` width exceeds mobile viewport, causing horizontal overflow
- **Violated Rule:** R-03 — Mobile Responsiveness (Hard Gate: HIGH)
- **Reason:** Forcing 5 desktop action buttons (`#apiStatusBadge`, `#themeToggleBtn`, `.whatsapp-btn`, `.nav-link-btn`, `#mobileMenuBtn`) side-by-side in a single row requires 556px, causing severe horizontal overflow and pushing the hamburger button off-screen on mobile screens (360px-480px).
- **Evidence:** DevTools measurement at 390px shows `.nav-actions` scrollWidth = `556px` vs container clientWidth = `358px` (overflow ~198px). The hamburger button is pushed past the right viewport boundary.
- **Proposed Fix:** Reflow secondary actions (`.whatsapp-btn`, `.nav-link-btn`, and expanded status text) into the mobile navigation drawer (`.nav-links`) when collapsed, keeping only essential controls (`.brand`, compact status dot, `#themeToggleBtn`, `#mobileMenuBtn`) in the top bar on mobile (< 640px).

### 3. [HIGH] R-03 (Mobile Responsiveness / antislop-layoutmobile: "Nav That Stays Desktop") — Desktop action links kept in top bar instead of reflowing into mobile pattern
- **Violated Rule:** R-03 — Mobile Responsiveness (Hard Gate: HIGH)
- **Reason:** Full CTA text button (`<span>WhatsApp</span>`) and external link (`<span>GitHub</span>`) remain forced in the top navbar row on narrow screens instead of adapting to a mobile navigation pattern.
- **Evidence:** `.whatsapp-btn` alone consumes ~120px on a 390px screen with full text label.
- **Proposed Fix:** Move full-width styled WhatsApp CTA and GitHub link into the mobile dropdown drawer (`.nav-links`) below the page anchor links, so they are spacious, thumb-friendly, and accessible when the menu is open.

### 4. [HIGH] R-03 (Mobile Responsiveness / antislop-layoutmobile: "Targets Too Close") — Crowded touch targets risk mis-taps on mobile
- **Violated Rule:** R-03 — Mobile Responsiveness (Hard Gate: HIGH)
- **Reason:** Due to 5 controls jammed into a single row with 0.5rem gap, buttons collide and touch each other, making reliable 44x44px touch operation impossible.
- **Evidence:** Overlapping visual bounds between `#apiStatusBadge`, `#themeToggleBtn`, and `.whatsapp-btn` on 390px viewport.
- **Proposed Fix:** Maintain comfortable 42px-44px touch targets with a clean 0.65rem gap between the remaining 3 controls in the mobile header, with zero overlap.

### 5. [MEDIUM] R-05 (Layout & Page Structure / Mobile Navigation) — Breakpoint step gap causes severe crushing between 481px and 768px
- **Violated Rule:** R-05 — Layout & Page Structure (Purpose-Gate: MEDIUM)
- **Reason:** Hiding of `.status-text` and `.nav-link-btn span` only triggers at `max-width: 480px`, leaving tablet and small landscape screens (481px-768px) with severe overcrowding where `.nav-actions` still consumes 556px.
- **Evidence:** At 502px width in DevTools, `.nav-actions` width is 556px and `.brand` is 0px.
- **Proposed Fix:** Elevate the breakpoint reflow to `max-width: 640px` and `max-width: 768px` so tablets and medium phones smoothly transition without content collision.
